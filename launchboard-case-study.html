Product engineering / Personal project

Launchboard.

A focused workspace for collecting opportunities and managing the work behind each application — from the first lead to interviews, deadlines, and follow-ups.

01 / The idea

Keep every opportunity moving.

Job, internship, and freelance opportunities are usually discovered across different websites and conversations. Once saved, the follow-up work can become fragmented: application status in one place, interview notes somewhere else, and important dates in a calendar or message thread.

Launchboard brings that personal workflow into one place. It is an organizer for opportunities found elsewhere — not a job board, recruitment platform, or freelancing marketplace.

Product goalMake it easy to capture an opportunity, understand its current status, and see the next action without losing the context around it.

03 / Architecture

Two data modes, with a clear boundary.

The browser-only workspace is the default. An authenticated workspace is available separately and uses the hosted API and database. The two modes do not synchronize automatically.

Account data is stored on the server and scoped to the authenticated account. The production application and API are deployed on Vercel.

Why keep the modes separate? The local workspace remains quick to try and usable without provisioning an account. The API workspace provides account-based persistence. Moving local records into an account is an explicit migration with a preview and backup safeguard — it is not silent background synchronization.

04 / Engineering decisions

Shared rules, explicit persistence, and account boundaries.

Shared TypeScript domain

A small workspace package holds shared types, validation rules, date helpers, limits, and backup normalization so frontend and server code can use the same domain definitions.

Separate persistence adapters

The UI can work with browser storage or the HTTP API without pretending that local and account data are one automatically synchronized store.

API validation and ownership

The Express API validates incoming data and scopes records to the authenticated account rather than trusting client-provided ownership.

Security-conscious sessions

The authenticated flow uses Argon2id password hashing, database-backed HttpOnly sessions, CSRF protection, origin checks, and account verification and recovery workflows.

Data portability

CSV supports tabular transfer, while JSON is the full-fidelity backup format for nested records, interviews, contacts, materials, activity, and archived data.

Deliberate operations

Database migrations are explicit release actions. Production credentials stay in hosting environment settings rather than in the frontend or repository.

06 / Quality and delivery

Built, tested, and deployed as a real application.

The project includes separate frontend and server test suites, a production build and type-check workflow, and GitHub Actions continuous integration. The hosted frontend and API are deployed on Vercel, with TiDB Cloud Serverless providing the authenticated workspace database.

Operational checks include API health and database-readiness endpoints. The project documentation also records important boundaries: the current rate limiter is process-local, so a shared store is needed before scaling across multiple application instances.

Launchboard is a personal learning and portfolio project. It is not presented as a security-certified or production-scale commercial service.
